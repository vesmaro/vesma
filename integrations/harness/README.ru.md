# Vesma harness pack — слой памяти для любого агентского харнеса

Эта директория — **канон для харнесов** при работе с сервером памяти Vesma:
16 скиллов `vesma-*` и один переносимый instruction (`vesma-memory-ops`),
которые может взять любой харнес — ZCode, VS Code Copilot, Pi, Claude Code,
Codex или любой читатель AGENTS.md-файлов.

## Контракт разделения слоёв

> **Слой памяти принадлежит Vesma, а не какому-либо агентскому фреймворку.**

Всё, что касается *работы с сервером памяти и его MCP-инструментами* —
скиллы, правила память-операций, канон имён инструментов — живёт здесь, в
репозитории Vesma. Агентские фреймворки держат максимум короткий указатель
на этот пак; собственной копии канона у них нет. До этого разделения скиллы
и канон гейтов G1–G4 жили в репозитории GCW (GithubCopilotWorkflow) и
разворачивались его инсталлятором; тот развёртывание выведено из
эксплуатации — копии GCW теперь стабы-указатели сюда.

## Контракт имён (прочтите до правок)

- **Имена инструментов — `vesma_*`** (`vesma_search`, `vesma_add`,
  `vesma_recall_context`, ...). Это соответствует brand-primary
  MCP-манифесту сервера (`VESMA_MCP_BRAND=vesma`). Легаси-написания
  `mnemos_*` принимаются сборками сервера до 6.0 — упоминать их можно
  только как явные заметки о совместимости.
- **Префиксы тегов — `mnemos:<subtype>`** (`mnemos:decision`,
  `mnemos:learning`, ...). Это контракт ДАННЫХ хранилища — он старше
  ребрендинга продукта и НЕ переименовывается. Не «чините» его.
- **Имена скиллов — `vesma-*`**; каждый файл несёт штамп пака
  `<!-- vesma-harness-pack: 1.0.0 -->`. Старый штамп
  `mnemos-integration` принадлежит серверному integration-паку (см. ниже)
  и в этом паке не встречается.

## Установка

```sh
./install.sh                            # ~/.zcode/skills + ~/.agents/skills
./install.sh --target /path/to/skills   # любая своя директория скиллов (повторяемо)
./install.sh --check                    # сверить установленные файлы с манифестами
./install.sh --uninstall                # удалить ровно то, что было установлено
./install.sh --force                    # обойти защиту от чужих файлов / смены версии
```

Инсталлятор:

- кладёт 16 скиллов как `<target>/vesma-<name>/SKILL.md`, а instruction —
  плоским файлом `<target>/vesma-memory-ops.instructions.md`;
- пишет целевой манифест `.vesma-harness-pack.manifest` (версия пака,
  время, sha256 каждого файла) — `--uninstall` и `--check` работают по
  манифесту, то есть удаляют/проверяют ровно то, что установили;
- отказывается перезаписывать файл на пак-пути, который сам не ставил
  (сначала удалите его или передайте `--force`);
- идемпотентен: повторный запуск обновляет файлы и манифест.

Без сети, без секретов, без записей вне целевых директорий.

## Как харнесу взять пак в работу

1. **Директории скиллов** — установите в директорию скиллов харнеса
   (nested-раскладка `<name>/SKILL.md` — кросс-харнесный стандарт).
   Описания скиллов насыщены триггерами, поэтому харнес подхватывает их
   нативно.
2. **Всегда активные правила** — гейты G1–G4 должны быть видны каждому
   агенту, а не только при срабатывании скилла:
   - харнесы стандарта AGENTS.md: добавьте 2–3 строки с summary гейтов и
     указателем на `vesma-memory-ops.instructions.md`;
   - VS Code Copilot: скопируйте `instructions/memory-ops.md` в
     `.github/instructions/` (frontmatter `applyTo: '**'` уже корректен).
3. **Регистрация MCP** — зарегистрируйте сервер Vesma в MCP-конфиге
   харнеса (ключ сервера `vesma`, рекомендуется `VESMA_MCP_BRAND=vesma`).
   Сниппеты для харнесов — в документации `vesma serve`/`vesma mcp-server`.
4. Первая сессия: харнес агента видит скиллы `vesma-*` и канон гейтов —
   с первой секунды специалист работает по правилам Vesma.

## Отношение к серверному integration-паку

Vesma возит ДВА набора артефактов для харнесов, с разными штампами
владения:

| | Серверный integration-пак (`integrations/skills`, `integrations/instructions`, `vesma util-setup`) | Этот harness-пак (`integrations/harness`) |
|---|---|---|
| Ставит | CLI сервера при настройке сервера (детект харнеса через `targets.yaml`) | пользователь / настройка репозитория через `install.sh`, сервер не нужен |
| Состав | плоские скиллы, включая `mnemos-canon-write`, `mnemos-context-lifecycle`, instruction канона записей, canon JSON Schema | 16 workflow-скиллов + instruction память-операций |
| Штамп | `<!-- mnemos-integration: ... -->` | `<!-- vesma-harness-pack: 1.0.0 -->` |
| Удаление | `vesma util-setup --uninstall` (inline-штамп или побайтовое совпадение) | `install.sh --uninstall` (манифест) |

Они дополняют друг друга, а не конкурируют: серверный пак учит канону
записей и разворачивает схемы; этот пак учит workflow памяти. Оба могут
жить в одной директории скиллов без конфликтов владения.

## Версионирование

Версия пака живёт в `install.sh` (`PACK_VERSION`) и в штампе каждого
файла. Меняйте вместе; инсталлятор отказывается перезанимать цель,
чья манифест-запись сделана другой версией пака, без `--force`.
