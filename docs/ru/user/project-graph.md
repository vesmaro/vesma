# Граф проектов

**🌐 Language / Язык:** [English](../../en/user/project-graph.md) · Русский

> Vesma умеет знать вашу кодовую базу так же, как сессии: в виде searchable-карты
> символов. Проиндексируйте проект один раз — и агенты получают схемы файлов,
> поиск по символам, трассировку вызовов и сниппеты диапазонов строк — с
> отфильтрованными секретами и без единого байта исходника в хранилище.

---

## Что это такое

**Граф проектов** — это карта символов кодовой базы уровня памяти, построенная
парсингом tree-sitter'ом (ADR-0032). Она живёт в sidecar-файле SQLite,
`code_graph.db`, рядом с основным хранилищем в data dir (по умолчанию
`~/.mnemos/data/`).

Что хранится — и что не хранится никогда:

| Хранится | Не хранится никогда |
|----------|---------------------|
| Пути файлов (repo-relative), языки, диапазоны строк | Содержимое файлов, байты исходника (PG1) |
| Имена и квалифицированные имена символов | Докстроки, комментарии, строковые литералы |
| Формы сигнатур (без значений по умолчанию) | Тела кода |
| Рёбра между символами, хэши содержимого | Секреты — они «травят» файл (см. ниже) |

Поскольку в графе нет байтов исходника, это *производные данные*: удалите —
и их всегда можно перестроить из источников. Sidecar не нуждается в бэкапах —
`code_graph.db` одноразовый по дизайну.

Узлы и рёбра:

| Вид | Примеры |
|-----|---------|
| **Узлы** | `Project`, `File`, `Module`, `Class`, `Function`, `Method`, `Type` |
| **Рёбра** | `CONTAINS_FILE`, `DEFINES`, `IMPORTS`, `CALLS`, `INHERITS`, `TESTS`, `USES` |

Ребро `USES` — маркер честности всего семейства: вызов записывается как
`CALLS`, только если парсер доказал цель; всё остальное, похожее на вызов,
получает `USES` с `provenance: heuristic`. Ребро из графа никогда не
претендует на большую уверенность, чем имеет.

## Включите граф для проекта

Граф индексирует **только зарегистрированные корни** (PG2). Корень — это
первый абсолютный путь в записи проекта (`paths[0]`). Регистрация — шаг
оператора: проекты, автосозданные записью памяти, не имеют путей, так что
вызовы графа для них отвечают отказом конфайнмента, пока вы не зарегистрируете
корень:

```python
from vesmaro.models import Project
mgr.sqlite.save_project(Project(name="vesma", paths=["/home/you/vesma"]))
```

Дальше поток — три вызова инструментов (каждый требует `agent` — см.
[Границы и FAQ](#границы-и-faq)):

1. **Индексация** — `mnemos_index_project` с `project_id` и `agent`. Первый
   запуск — полная индексация; последующие — инкрементальные по умолчанию
   (пропуск, когда ничего не изменилось, по классификации mtime+size).
2. **Проверка** — `mnemos_project_graph_status`: объёмы узлов/рёбер/файлов,
   процент fresh, ошибки разбора и число poisoned-файлов.
3. **Использование** — `mnemos_search_graph` для ранжированного поиска по
   символам, `mnemos_get_file_outline` для схемы файла, `mnemos_trace_path`
   для обходов вызовов/навигации, `mnemos_get_code_snippet` для диапазонов
   строк.

> **В текущем релизе ничего не индексируется само.** Первая индексация —
> всегда явный вызов. Фоновой авторегистрации и индексации «по первому
> касанию» нет: зарегистрированный watch поддерживает свежесть уже
> проиндексированного проекта, но первый индекс никогда не создаёт.

## Поддерживайте свежесть: watch-опрос

`mnemos_watch_start` регистрирует проиндексированный проект во
внутрипроцессном потоке опроса (без демона). На адаптивном интервале — база
5 с, +1 с за каждые 500 проиндексированных файлов, потолок 60 с — он
классифицирует файлы по mtime+size и переиндексирует только при фактических
изменениях, с аудитом под причиной `watch`.

- Регистрации живут в пределах процесса; перезапуск их сбрасывает.
- Глобальный потолок: 8 активных регистраций
  (`code_graph.watch_max_registrations`).
- `mnemos_watch_status` показывает все регистрации и исход последнего опроса;
  `mnemos_watch_stop` останавливает одну или все (идемпотентно).

## Десять инструментов

| Инструмент | Что делает |
|------------|------------|
| `mnemos_index_project` | Полная или инкрементальная индексация зарегистрированного корня; сериализуется по проекту |
| `mnemos_project_graph_status` | Объёмы, свежесть, ошибки разбора, число poisoned-файлов по проекту |
| `mnemos_search_graph` | Ранжированный поиск по имени / квалифицированному имени / пути; сигнатуры — opt-in |
| `mnemos_trace_path` | BFS по рёбрам от одного символа (глубина ≤ 2, честный флаг `truncated`) |
| `mnemos_get_file_outline` | Схема символов одного файла — формы, никогда тела |
| `mnemos_get_code_snippet` | Диапазон строк читается **с диска**, с проверкой свежести и сканом на секреты |
| `mnemos_check_graph_coverage` | Вердикт по пути: `indexed` / `stale` / `parse-error` / `unindexed` / `poisoned` |
| `mnemos_get_graph_schema` | Карта контракта: виды, лимиты, токен-контракт |
| `mnemos_list_graph_projects` | Зарегистрированные проекты вместе со статусом индекса |
| `mnemos_delete_graph_project` | Удалить индекс (только sidecar); единственный способ очистить poisoned-набор |

Плюс watch-семейство: `mnemos_watch_start` / `mnemos_watch_stop` /
`mnemos_watch_status`.

Каждый оконный инструмент принимает `max_output_tokens` (128–1 000 000,
по умолчанию 3200) под детерминированным токен-контрактом: строки
отбрасываются целиком, никогда не режутся, курсор строго сдвигается вперёд. Полные
входные схемы и примеры: [mcp-tools.md, «Инструменты графа
проектов»](mcp-tools.md#инструменты-графа-проектов-adr-0032).

## REST-зеркала

Та же поверхность доступна по HTTP ([http-api.md](http-api.md#граф-проектов-adr-0032)):

- `/graph/index`, `/graph/status/{project_id}`, `/graph/search`,
  `/graph/trace`, `/graph/outline`, `/graph/snippet`, `/graph/coverage`,
  `/graph/schema`, `/graph/projects`, `DELETE /graph/projects/{project_id}`
- `/watch/start`, `/watch/stop`, `GET /watch/status`

## Безопасность и ограждения

Модель безопасности — ADR-0032 §6 (инварианты PG1–PG7); вот что она значит
для вас:

| Ограда | Что вы видите |
|--------|---------------|
| **Конфайнмент (PG2)** | Касаются только корней, зарегистрированных оператором. Произвольные пути, symlink-побеги и обход через `..` отклоняются. |
| **Poisoned-файлы (PG3)** | Файл, сработавший в детектор секретов при индексации, отравлен **навсегда**: символы остаются в графе, сниппеты не выдаются никогда. Набор чистит только `mnemos_delete_graph_project`. |
| **Скан при выдаче (PG4)** | Сниппеты читаются с диска в момент запроса — кэша сниппетов нет. Расхождение mtime+size+sha256 даёт маркер `stale`, но не содержимое; секрет в запрошенном диапазоне отклоняет весь диапазон, fail-closed. |
| **Fail-closed лимиты (PG7)** | 20 000 файлов / 500 МБ на проект. Превышение отклоняет ВЕСЬ индекс — частичный граф не публикуется никогда. |
| **Export-blind (PG5)** | Карта кода не покидает сервер: export-бандлы и payload'ы federation/mesh никогда не несут артефактов графа. Пиры индексируют собственные локальные источники. |
| **Атрибуция и аудит (PG7)** | Каждый вызов — чтение или запись — аудируется по агенту; вызовы без `agent` отклоняются с `attribution-required`. |
| **Ноль байтов исходника (PG1)** | Откройте sidecar — там имена, пути, диапазоны строк; ни кода, ни литералов, ни секретов в покое. |

## Конфигурация

Все флаги живут под `code_graph:` в `config.yaml` (см. `config.example.yaml`).
Поверхность **включена по умолчанию** (решение владельца 2026-09-28).

| Ключ (`code_graph.`) | По умолчанию | Значение |
|----------------------|--------------|----------|
| `enabled` | `true` | Мастер-флаг 10 инструментов + REST-namespace `/graph/`; `false` скрывает всю поверхность (каждый вызов отвечает `code: "disabled"`). |
| `beacon` | `true` | Одна строка-хвост в выводе `assemble_context` со свежестью графа («indexed …, N/M files fresh — call mnemos_search_graph»). Только при `enabled`. |
| `watch` | `true` | Взводит watch-опрос (`mnemos_watch_start`); инертен до явной регистрации. |
| `index_max_files` | `20000` | Жёсткий лимит проиндексированных файлов на проект (fail-closed). |
| `index_max_source_mb` | `500` | Жёсткий лимит суммарных байтов исходника на проект, МиБ (fail-closed). |
| `watch_max_registrations` | `8` | Глобальный потолок активных watch-регистраций на процесс. |
| `watch_base_interval_sec` / `watch_interval_per_500_files` / `watch_max_interval_sec` | `5.0` / `1.0` / `60.0` | Адаптивный интервал опроса: база + 1 с за каждые 500 файлов, с потолком. |

Переопределение через окружение — по каноническому шаблону настроек:
`VESMARO_CODE_GRAPH__INDEX_MAX_FILES`,
`VESMARO_CODE_GRAPH__INDEX_MAX_SOURCE_MB`.

## Границы и FAQ

- **Почему каждый вызов требует `agent`?** Атрибуция PG7: аудит-трейлы и
  ответственность по агентам. `mnemos_recall_context` не несёт `agent`, так
  что поверхность графа никогда не ездит на нём — передавайте идентификатор
  вызывающего явно.
- **Мой проект — голый checkout с `.git` / без packaging-манифеста.**
  Нормально — регистрация идёт по записи проекта, а не по детекции
  манифеста. Дайте проекту абсолютный `paths[0]` и проиндексируйте.
- **Несколько путей у одного проекта?** Граф индексирует первый
  зарегистрированный путь (`paths[0]`) — один корень, один граф на проект.
- **Файл изменился после индексации.** Сниппеты вернутся с маркером `stale`
  вместо содержимого; переиндексируйте (или пусть это делает watch-опрос),
  чтобы обновить.
- **Как выключить всё?** `code_graph.enabled: false` — инструменты отвечают
  `disabled`, маячок прячется, ничего не индексируется.
- **Нужен ли бэкап `code_graph.db`?** Нет. Это перестраиваемый sidecar в
  data dir; `mnemos_delete_graph_project` удаляет только индекс, но не
  сущность проекта и не его памяти.
