# Рантбук: MCP-инжектор токена (бесшовный доступ харнесов)

**🌐 Language / Язык:** [English](../../../en/admin/runbooks/mcp-token-injector.md) · Русский

Архитектура: [ADR-0052](../../../project/adr/0052-seamless-harness-mcp-token-injector.md) ·
Доктор-проба: **DR-26** (`vesma doctor`) · Генератор: `vesma service injector-unit`

## Что это

Loopback MCP-слепой прокси на stdlib (`vesma.mcp_injector`) стоит между харнесом и
`/mcp`-плоскостью ядра. Харнес аутентифицируется статическим секретом листенера;
прокси на КАЖДЫЙ запрос перечитывает токен-файл и инжектит ровно один свежий
Bearer к ядру. Сессия любого возраста переживает любое число ротаций.

- **Канонический источник:** `src/vesma/mcp_injector.py` (репо-артефакт, stdlib only).
- **Живая деплойка (host-local):** `~/.local/bin/vesma-mcp-injector` + юнит
  `vesma-mcp-injector.service` (systemd --user) — развёрнутая копия; обслуживает
  прод до следующего обновления, которое заберёт репо-артефакт.

Канон портов (аддендум ADR-0052): 8787 ядро REST/MCP · **8789 инжектор zcode** ·
8790 mesh.tcp (в ядре) · 8791 mesh-компонент · 8792 mcp-front · следующие
харнесы — с 8793. ОДИН инжектор на идентичность харнеса: порт + токен-файл +
секрет-файл = идентичность.

## Ротационный инвариант (не откатывать)

**Период ротации строго меньше TTL токена.** Каденс 2×/сутки (04:17 + 16:17,
таймер `Persistent=true`) при TTL 24ч даёт перекрытие ≥12ч — инвариант ВРЕМЕНИ.
Один 401-ретрай прокси, ТОЛЬКО при байт-изменении токен-файла, закрывает
миллисекундную гонку вокруг атомарного `mv` — инвариант КОДА. Обязательны оба:

- откат каденса на daily молча возвращает суточное окно гонки без внешних
  симптомов — DR-26 предупреждает, когда mtime токен-файла старше 25ч
  (ротационная автоматизация остановилась);
- ротационный скрипт НИКОГДА не перезаписывает конфиг харнеса (конфиг
  write-once: URL литералом + секрет листенера).

## Деплой инжектора нового харнеса (user-плоскость)

```sh
# 0. Минт токен-файла идентичности и секрета листенера, оба 0600.
# 1. Рендер юнита из пинов идентичности (read-only печать):
vesma service injector-unit \
  --token-file ~/.secrets/vesma_zcode_agent_token \
  --secret-file ~/.secrets/vesma_proxy_listener_zcode.secret \
  --port 8789 --upstream-port 8787 > ~/.config/systemd/user/vesma-mcp-injector.service
# 2. Активация:
systemctl --user daemon-reload
systemctl --user enable --now vesma-mcp-injector.service
# 3. Конфиг харнеса → http://127.0.0.1:8789/mcp/ с
#    Authorization: Bearer <секрет листенера> — затем разовый рестарт харнеса.
# 4. Проверка: vesma doctor (DR-26) + healthz ниже.
```

## Порядок окна флипа (миграция на прокси — пункт приёмки)

1. Ротационный скрипт БЕЗ config-rewrite — ПЕРВЫМ (до флипа конфига он мнтит и
   атомарно кладёт токен ровно как раньше).
2. Флип конфига харнеса (атомарная запись, 0600): URL литералом
   `http://127.0.0.1:8789/mcp/` + секрет листенера как Bearer.
3. Разовый рестарт идущих сессий (клиент читает конфиг один раз на старте —
   честный физический предел; после него возраст сессии значения не имеет).

## Здоровье и диагностика

```sh
curl -s http://127.0.0.1:8789/healthz
# -> {"ok": true, "token_file_readable": true, "upstream_tcp_ok": true}
#    (без auth; в теле нет путей/версий/пидов — контрактная форма)
journalctl --user -u vesma-mcp-injector -f
# одна структурная строка на запрос: peer=... METHOD path -> status dur_ms retried token_changed
# WARN на каждый отказ auth (listener auth mismatch) и на каждый не-loopback peer
vesma doctor   # DR-26: юнит active? healthz? креденшел-файлы 0600 и свежие?
```

429 от прокси — сброс нагрузки, НЕ отказ авторизации — для бурстного харнеса
поднимите `--rate-max`. 503 `auth source unavailable` — fail-closed: почините
креденшел-файл (0600), прокси восстановится сам (Restart=always).

## Откат (минуты; дрель ДО флипа живых сессий)

1. Конфиг харнеса → прямой URL ядра с Bearer от живого токен-файла (атомарно, 0600).
2. Восстановить ИСХОДНЫЙ ротационный скрипт С шагом config-rewrite (.orig-бэкап)
   и v1 таймер — БЕЗ этого шага следующий ротационный прогон оставит сессии на
   старом конфиге, и дефект вернётся.
3. `systemctl --user disable --now vesma-mcp-injector.service`.
4. Разовый рестарт идущих сессий.
