# Runbook: Обновление зависимостей и напоминание о CVE

**🌐 Language / Язык:** [English](../../../en/admin/runbooks/dependency-updates.md) · Русский

## Причина существования этого runbook'а

Исторически runbook отслеживал игнорируемую `CVE-2026-45829` в `chromadb` (апстрим-фикса
не было). С NM-1c (ADR-0021) chromadb **убран из рантайма** — заменён встроенной локальной
моделью `vesma-embed-v1` — и его CVE ушли вместе с ним. Runbook остаётся ради того, что
по-прежнему актуально: политика прямых pin'ов для уязвимых транзитивных зависимостей и
еженедельная аудиторская проверка.

## Политика закрепления версий (M15.5.1)

Vesma использует **прямые pin'ы** для уязвимых транзитивных зависимостей вместо
обновления родительских пакетов:

- **`aiohttp>=3.14.3,<4.0`** — прямой pin. Изначально подтягивался транзитивно
  через `chromadb → kubernetes` (историческое: chromadb убран в NM-1c); floor
  подняли до 3.14.3 (#267): PYSEC-2026-3546/3547 фиксятся в 3.14.2,
  PYSEC-2026-3545 — в 3.14.3, так что 3.14.3 закрывает все три вместе с более
  старым CVE-пакетом (34993, 47265, 50269, 54273-54280). Pin остаётся, потому
  что уязвимые версии aiohttp по-прежнему достижимы через
  `fastapi`/`uvicorn`. Прямое закрепление безопасной минорной версии имеет
  меньший радиус взрыва, чем обновление родительского пакета.

- **`starlette>=1.3.0,<2.0`** — прямой pin, закрывает CVE-2026-48817, 48818,
  54282, 54283. Подтягивается транзитивно через `fastapi`. Та же логика.

- **Семейство pin'ов M15.5.2** (`pyproject.toml`): `pyjwt>=2.15.0`
  (PYSEC-2026-120/175-179 в 2.13.0, 4140-4152 в 2.14.0, 4141 в 2.15.0;
  PYSEC-2026-4146 без апстрим-фикса — игнорируется в `make security`,
  трекинг в #476), `urllib3>=2.8.0`, `python-dotenv>=1.2.2`,
  `idna>=3.15`, `pygments>=2.20.0`.

- **`pip`** — инструмент, а не зависимость проекта (в `pyproject.toml` не
  входит): обновлять через `pip install --upgrade pip` после пересоздания
  venv. В актуальном графе стоит 26.2.x — закрывает PYSEC-2026-196 и позже.

- **`chromadb`** — убран из рантайма в NM-1c (ADR-0021): встроенная модель
  `vesma-embed-v1` работает напрямую на `onnxruntime`. Обновлять больше нечего;
  запись оставлена как история решения.

При добавлении нового pin'а: включить однострочный комментарий в `pyproject.toml`
с CVE id и версией фикса, как в существующих записях. Pin'ы должны использовать
диапазон с верхней границей (`<4.0`, `<2.0`) во избежание случайного major-дрейфа.

## Еженедельная быстрая проверка

```bash
cd /path/to/vesma   # корень репозитория
source .venv/bin/activate
make security
```

Ожидаемые исходы:
- Чистый `pip-audit` → делать ничего не нужно.
- Новая CVE в транзитивной зависимости → добавить прямой pin по политике выше
  (или поднять родительский пакет, если фикса именно в нём).

## Полное обновление зависимостей

```bash
cd /path/to/vesma   # корень репозитория
source .venv/bin/activate
make update-deps
```

Затем запустить полные проверки проекта:

```bash
make verify
```

## Удаление временного игнора CVE после фикса

Target `security` в [Makefile](../../../../Makefile) несёт два ignore-флага:
`--ignore-vuln CVE-2026-45829` (бывшее исключение для chromadb — инертен с тех
пор, как chromadb убран из рантайма) и `--ignore-vuln PYSEC-2026-4146`
(адвизори pyjwt без апстрим-фикса, трекинг #476 — НЕ удалять, пока фикс не
вышел). Когда chromadb исчез из всех развёрнутых окружений:

1. Открыть [Makefile](../../../../Makefile)
2. В target'е `security` удалить `--ignore-vuln CVE-2026-45829` (keep-флаг
   `PYSEC-2026-4146` держим, пока открыт #476)
3. В target'е `security-reminder` удалить строки о устаревшем ignore
4. Запустить:

```bash
make verify
```

## Операционная политика

- Держать ignore только пока апстрим не выпустил фикс.
- Держать напоминание активным, пока существует ignore.
- Удалить и ignore, и напоминание в одном коммите после обновления.
