# Карта функционала

**🌐 Language / Язык:** [English](../en/features.md) · Русский

> Vesma — слой памяти для AI-агентов: одно подключение — и харнес получает
> долгосрочную память: структурированную, с поиском, защищённую контрактом —
> она переживает сессии, рестарты и сжатие контекста.

Одна страница, три честных секции: что работает из коробки, что частично,
что в плане. Статусы отражают кодовую базу v4.0.0 (карта владельца
2026-08-31, обновлена 2026-09-05: упаковка выпущена, бенчмарк-стенды готовы).

## Работает из коробки

Подключил — и есть. Ничего из таблицы не требует дополнительной проводки.

| Возможность | Что даёт |
|-------------|----------|
| **Универсальное подключение** | MCP-сервер (38 инструментов, stdio) + REST API — любой харнесс с поддержкой MCP подключается одной строкой. Подробнее: [mcp-tools.md](user/mcp-tools.md), [http-api.md](user/http-api.md) |
| **Готовые интеграции** | zcode, стандарт `~/.agents` (Claude Code, Codex, Continue, Qwen и др.), pi — через `vesma integration`: универсальные таргеты развёртывания, однострочные MCP-пресеты, доктор мульти-харнесов (`vesma doctor` проверяет регистрацию MCP в известных харнессах). См. [руководство по интеграции](user/integration-guide.md) |
| **Пакет скиллов** | 14+ скиллов памяти деплоятся в харнесы вместе с инструментами |
| **Гибкая память** | Гибридный поиск (полнотекстовый + векторный, слияние ранжирования), [теги-контракт](user/tag-contract.md), память по агентам и по проектам, [контекстный фильтр](user/context-filter.md) с профилями (code / docs / web / logs …), сжатие CCR — маркер в контексте, оригинал в памяти, экономия 70–90% токенов |
| **Динамическая сборка контекста** | `assemble_context`: конвейер поиск → сжатие → фильтр → скан секретов → выравнивание кэша → бюджет токенов, провенанс каждого блока |
| **Мост контекста харнесса** | `on_context_rewrite`: при сжатии истории харнессом оригинал сохраняется без потерь и доступен по требованию ([ADR-0018](../project/adr/0018-context-rewrite-ltm-bridge.md)) |
| **Хуки жизненного цикла** | `pre_llm_call` (впрыск контекста перед запросом модели), `on_session_start`, `post_tool_call` (авто-сжатие выводов инструментов) |
| **Модель публикации v3.0.0** | Запись видна сразу после сохранения; фоновая дообработка с бесшовной подменой; карантин опасного контента с нейтральной ретракцией ([ADR-0019](../project/adr/0019-optimistic-publication-async-refinement.md)) |
| **Автозащита** | Детекторы инъекций и секретов на входе и публикации; скан каждой выдачи; полный аудит с привязкой к записи |
| **Автоконвейер** | Фоновый обработчик: кластеризация, дедупликация, гейт качества, публикация |
| **Встроенная модель эмбеддингов** | `vesma-embed-v1` (~30 МБ int8 ONNX) поставляется внутри wheel — гибридный векторный поиск работает полностью офлайн, на CPU, без скачиваний и API-ключей |
| **Упаковка и доставка** | PyPI [`vesma`](https://pypi.org/project/vesma/) — доребрендинговый wheel `mnemos-memory-server` остаётся до deprecation; (wheel несёт integration-пак и модель), npm `pi-vesma` + алиасы, GHCR-образ `ghcr.io/vesmaro/vesmaro`, однострочный скрипт-установщик, фреймворк бенчмарков S1–S4 в репозитории |

### Граф проектов — кодовая база становится памятью (5.1.0)

**Граф проектов** (ADR-0032, включён по умолчанию) отображает
зарегистрированный корень проекта в граф символов: схемы файлов,
ранжированный поиск по символам, трассировка вызовов и сниппеты диапазонов
строк, с детерминированным токен-бюджетом на каждом ответе. Десять
MCP-инструментов + REST-namespace `/graph/` + watch-опрос, переиндексирующий
при реальных изменениях. Безопасность встроена: ноль байтов исходника в
хранилище, секреты навсегда «травят» сниппеты файла, сниппеты перечитываются
с диска и сканируются при каждой выдаче, лимиты fail-closed, карта никогда
не покидает сервер через export или федерацию, каждый вызов аудируется по
агенту. Полный гид: [project-graph.md](user/project-graph.md).

## Частично — ядро есть, полнота в работе

| Область | Статус |
|---------|--------|
| **Автономность (~90%)** | Хранилище, поиск, сборка контекста и защита работают сами. Дисциплина хуков в произвольном харнессе обеспечивается задеплоенными инструкциями и скиллами (мягкая автоматика), а не жёсткой проводкой. Жёсткая проводка есть у Hermes-адаптера и частично у zcode; универсальный механизм хуков для любого харнесса — в плане |
| **Дообработка «мозгом» (LLM)** | Конвейер работает; кластеризация, дедупликация и гейт качества — настоящие. Качественное обогащение текста — детерминированная заглушка; LLM-провайдер подключается в зарезервированную точку интерфейса (в плане) |
| **Decision provider — стык «семантического if»** | Один типизированный интерфейс (ADR-0004 канона) с тремя реализациями: детерминированный базовый провайдер (по умолчанию), встроенная модель `vesma-cortex-v1` (ниже) и опциональный внешний Jev-адаптер. Стык ещё не подключён к продуктовым решениям — провайдеры открыты и измеряются, проводка в точки вызова — волна позже |

### Decision provider: vesma-cortex-v1 (W5d)

**Модель cortex** — самодостаточный ONNX-артефакт ~96 КБ
(`vesma-cortex-v1`), поставляемый внутри wheel: градиентный бустинг над
13 замороженными признаками пары, отдающий калиброванную
P(дубликата) для вопросов о почти-дубликатах поверх подготовленных пар
записей. Отобрана предрегистрированной калибровкой против
детерминированного базового провайдера (запечатанный holdout:
sensitivity 1.0, specificity 0.98, Brier 0.0053 против 0.81 у базового).

Вместе с бандлом едут жёсткие гарантии: eager-загрузка с полным проходом
валидации (идентичность, гейт ≤5 МБ, sha256 весов в телеметрию,
замороженный хэш состава фич и **пин эмбеддера** — при несовпадении
живой модели эмбеддинга с той, на которой калибровалась модель, следует
громкий отказ как событие перекалибровки); ноль сетевых импортов
(AST-хранитель); любой отказ `CORTEX-E-*` деградирует на
детерминированное правило с машино-парсируемым предупреждением — ingest
никогда не блокируется. Включается конфигом
`decision_provider = "vesma"`; **по умолчанию выключена** — флип флага
остаётся решением владельца после опытной обкатки.

## В плане

| Фича | Объём |
|------|-------|
| **Граф памяти** | Связи записей, каскад цитирований ([ADR-0017](../project/adr/0017-memory-system-evolution-roadmap.md)) |
| **Федерация между устройствами** | Постоянный канал обмена; сейчас — пакетный обмен файлами ([ADR-0017](../project/adr/0017-memory-system-evolution-roadmap.md)) |
| **Мульти-принципал** | Память нескольких владельцев с изоляцией |
| **Мета-уровень: дорожки выдачи (lanes)** | Детерминированные дорожки (rules / decisions / knowledge) как под-этап recall в `assemble_context` — раскатываются только если предрегистрированный эксперимент A/B/B0 побьёт тривиальный бейзлайн ([ADR-0025](../project/adr/0025-memory-meta-level-lanes.md)) |
| **Каскад свёртки — «свёртка с чеками»** | Синтез сессия → проект → кросс-проект над кластерами: автоматический по умолчанию, но никогда безусловный по авторитету — итоги рождаются без `applyTo:`/`severity:`, ничто не пиннится без оператора, каждый результат возводим к исходникам ([ADR-0025](../project/adr/0025-memory-meta-level-lanes.md)) |
| **Awareness — присутствие и дельта** | Чем занят каждый агент и что изменилось с вашего последнего взгляда, с подсказками о конфликтах — строится из фактов, наблюдаемых сервером; нервная система, а не дирижёр ([ADR-0025](../project/adr/0025-memory-meta-level-lanes.md)) |
| **Операционная картина (swarm v0a/v0b)** | Соседи по проекту — по строке на каждого: id агента, последняя активность, счётчик записей в окне, наличие чекпоинта; только счётчики/ids/времена, строго в рамках проекта, с капом частоты, никогда не закрепляется. Swarm v0b добавляет ЗАЯВЛЕННУЮ соседом задачу (`task:<slug>`, ADR-0027) — самоподанная метка: скан на выдаче fail-closed, рендер в маркированном `[unverified]`-подразделе, никогда в наблюдаемых фактах или блоках |

Инвариант роадмапа мета-уровня: **ноль тихих потерь** — факт либо сохранён, либо потеря видна в
отчёте; каждая ступень выше открывается только после измеренного подтверждения.
