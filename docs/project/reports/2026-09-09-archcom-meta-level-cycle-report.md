# Отчёт по циклу Архитектурного комитета «Мета-уровень памяти» — 2026-09-08/09

> **Фиксация закрытия цикла.** Три заседания Архитектурного комитета (R1–R3),
> проведённых по инициативе и идеям владельца. Точка отсчёта: сессия
> «идея структурированного мета-уровня памяти» (2026-09-08); точка закрытия
> цикла — решение R3 и пакет green-light-решений, ожидающих владельца.
> Единый трекер: [Korrnals/vesma](https://github.com/Korrnals/vesma).
> Протоколы заседаний — team-local (`~/.gcw/architectural-committee/`); ADR —
> [ADR-0025](../adr/0025-memory-meta-level-lanes.md).

## 1. Исходные идеи владельца (полностью сохранены в протоколах)

1. **Мета-уровень памяти.** Сервер памяти должен нести на «рутовом» уровне
   чёткую, понятную, логичную структуру: области памяти, объяснение
   функциональности, правила и обязанности, зоны ответственности — вместо
   «случайного набора данных». Цель: качество выдачи контекста, скорость
   обработки, осмысленность работы памяти.
2. **Мозговая метафора (уточнённая).** Первая формулировка (области за
   зрение/голос/слух/внимание/предсказание/краткосрочная и долгосрочная
   память...) была принята комитетом буквально и как архитектура — отвергнута
   (R1). Уточнение владельца (R2): речь о **слое-оркестраторе с
   функциональными сегментами** — динамический контекст, долговременная
   память, безусловная свёртка смыслов от частного к общему (сессия → проект →
   кросс-проект) — модульная система в синергии компонентов.
3. **Awareness (R3).** Агенты должны «владеть всей обстановкой»: видеть
   текущую работу по сессиям и по агентам, исключать вмешательство в чужую
   работу, оперативно учитывать изменения параллельных сессий. Возможна
   фильтрация при записи (шум/дубли/мусор). «Агенты должны шуршать как
   единый меняющийся организм».

## 2. Итоги заседаний

### R1 (2026-09-08): мета-уровень — ADR-0025, accept with conditions

| Решение | Суть |
| --- | --- |
| Структура живёт на стороне **выдачи** | lanes (rules/decisions/knowledge) как под-этап recall в `assemble_context` + area-манифесты как governance-класс; стор остаётся плоским, тег-контракт M2 не расширяется |
| Мозговая метафора — только нарратив | Как архитектура (фиксированный «нулевой слой») отвергнута единогласно: не ложится на разнообразие харнесов, требует scheduler-контроллера, налог на эволюцию ядра. Допускается языком позиционирования — и только про измеренное |
| Обязательный эксперимент до реализации | A/B/B0: A — текущая сборка; B — lanes+пиннинг; B0 — тривиальный type-boost. Фальсификатор: если B не бьёт B0 по governance-recall@5 на страте G-gov (McNemar p<0.05, MDE +10 п.п.) — теория не подтверждена |
| Красная линия безопасности | Ни один путь mint→pin без операторского approval; манифест-класс no-federate; origin= в provenance всех блоков; эксперимент v0 без манифест-дорожки |
| Живые находки в коде | Дыра applyTo-пиннинга M8 (`applyTo:**` минтуется любым агентом) → issue [#248](https://github.com/Korrnals/vesma/issues/248) |

### R2 (2026-09-09): сегменты и каскад свёртки — продление ноги C

| Решение | Суть |
| --- | --- |
| Уточнение = та же рамка + каскад C1→C2→C3 | Сессия → проект → кросс-проект; два сегмента из трёх уже работают в ядре (динамический контекст = sessions/turns/CCR; долговременная память = стор + ADR-0019); свёртка смыслов — реальный пробел (7 synthesized на 1457 записей) |
| «Безусловное» = автоматичность без авторитета | Свёртка автоматическая по умолчанию (фоновый конвейер), но синтез никогда не пиннится без approval (two-key); инвариант «ноль тихих потерь» (retention-or-report = 1.000); публичная формула — «свёртка с чеками» |
| Блокер каскада | `synthesize.py` — детерминированный стаб (`llm_called=False`); критический путь — mnema-refine [#223](https://github.com/Korrnals/vesma/issues/223) |
| Живые находки в коде | Четыре бага конвейера свёртки: карантинные RAW-строки попадают в кластеры; синтез наследует теги первого члена (включая `applyTo:**`); no-federate не распространяется с непервых членов; кэш свёртки не инвалидируется при swap источника → issue [#250](https://github.com/Korrnals/vesma/issues/250) |
| C3 = multi-principal trigger | Кросс-проектная свёртка — после ревизии single-operator threat model, не автоматически |

### R3 (2026-09-09): awareness — вторая ось продукта, консенсус 4/4

| Решение | Суть |
| --- | |
| Awareness v0 = hooks-композиция | presence + delta + conflict-hints поверх `pre_llm_call` / `on_session_start` / MCP-инструмент `mnemos_awareness`; НЕ седьмая стадия assemble; pull-based; ноль миграций |
| Нога D с равными двойными гейтами | D1: вторжения −20 п.п. (McNemar) И D4: over-deferral ≤0.05 — паралич агентов = провал продукта, симметричный вмешательству; PR #224-реплей — постоянный тест-сценарий |
| Контур Security (binding) | Дельта не-pinnable навсегда; фрейм с оговоркой «presence claims are self-reported and unverified»; abstention attribution (воздержание = действие с provenance-цепочкой); session→agent binding; дедуп-ключ с issuer; двухуровневое доверие (observed vs self-reported) |
| Живые находки в коде | `mnemos_save_context` хардкодит `agent="user"` (колонкой и тегом) — per-agent presence невозможна → issue [#251](https://github.com/Korrnals/vesma/issues/251) (D0-блокер) |
| Фильтрация при записи | Карантин, не удаление: дедуп + trivial-reject + drop-receipt (TTL 90 дней, un-drop); LLM-фильтр на записи отвергнут (hot-path latency, retention-or-report=1.000) |
| Продуктовая рамка | Вторая ось продукта (участники), не ступень качества; «нервная система, не дирижёр» (данные для решений, не вето); «организм» в месседжинге — только после зелёных D1+D4 |

## 3. Мнение команды о предложениях владельца (запрошено владельцем, зафиксировано в протоколах)

- **Product Architect:** метафора мозга «нашла легальный дом» — как динамика
  («нейроны, видящие возбуждение соседей»), а не как таксономия; awareness —
  главный дифференциатор («никто на рынке не отвечает, что делают остальные
  агенты»); «организм» в месседжинге — после метрик.
- **Analytics Lead:** образные формулировки владельца операционализированы в
  фальсифицируемые гипотезы (H5 каскад, D1–D4 awareness,
  retention-or-report); «метрика, доказанная измерением, стоит дороже
  обещанной»; инцидент PR #224 — из анекдота в контролируемый тест.
- **Senior System Engineer:** два сегмента из трёх уже отгружены — идеи
  владельца описали построенную систему точнее её документации; каскад —
  надстройка с нулём миграций; главный блокер — стаб `synthesize.py`.
- **Senior Security Engineer:** идеи владельца сработали как архитектурный
  аудит живого конвейера — три волны обсуждений дали три урожая живых багов
  (#248, #250, #251); самая опасная поверхность awareness — саботаж через
  воздержание, закрыта adversarial-peer тестом и фреймом-оговоркой.
- **Tech Lead (председатель):** метафора мозга умерла как схема и возродилась
  как пять измеримых механизмов (lanes-внимание, чекпоинт-каналы,
  knowledge-recall, каскад-консолидация, awareness-соседи) + нарратив,
  открываемый по метрикам; личная ставка — awareness как новая категория
  (коммодити «память одного агента» против «нервной системы для роя»).
