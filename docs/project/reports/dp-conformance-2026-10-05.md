## Выравнивающие правки (по дельтам review-2)

Все правки — в двух файлах реализации (`src/vesmaro/decision_provider.py`,
`src/vesmaro/decision_jev.py`) и трёх тестовых; переработки провайдеров нет —
только контрактные точки.

1. **§3.8 классы действий (fix a).** Каждая машинно-парсируемая
   деградация теперь несёт `class=` из фиксированного множества
   `{provider-class, verdict-class, call-class}` (константы
   `ACTION_CLASS_*` в `decision_provider.py`). Покрыты: три загрузочных
   warn в `resolve_decision_provider` (`CORTEX-E-PIN`/`CORTEX-E-LOAD`,
   `provider-class`), per-verdict warn в `VesmaProvider.evaluate`
   (`verdict-class`), warn-строки Jev получили `code=JEV-E-*`
   (`_ask` — контекст отказа, `JEV-E-INFER`; деградация — у wiring-обёртки),
   отказы гейта/сканера — `call-class` (п. 2). Тест-парс всех трёх
   классов: `test_degradation_warns_carry_the_contract_action_class`,
   `test_privacy_refusal_warns_with_call_class`,
   `test_scanner_exception_is_fail_closed`,
   `test_resolver_*` (усилены ассертами на класс).
2. **§3.5 fail-closed сканера + `no-federate` до сборки (fix b).**
   Скан гейта обёрнут в `_scan_fail_closed`: исключение детектора ИЛИ
   таймаут (стенной часы, `JEV_SCAN_TIMEOUT_SECONDS = 10s`, worker-тред)
   → типизированный `JevScannerError` + warn
   `code=JEV-E-SCANNER class=call-class`, вызов прерван целиком, ноль
   сети. Внутренняя ошибка danger-детектора (он возвращает её полем
   `DetectionResult.error`, не исключением) разведена с находкой:
   `error` → сканер-отказ (`JEV-E-SCANNER`), находка → `JEV-E-GATE`;
   оба класса действий — `call-class`. Первая линия `no-federate`:
   `CanonRecordView.from_memory` отказывает проекции записи с тегом
   (`NoFederateRecordError`) — помеченная запись физически не может
   попасть в подготовленное состояние; порядок «тег до скана» внутри
   гейта сохранён и задокументирован.
3. **§3.6 область калибровочного гейта (fix c).** Проверка кода:
   гейт и так не задевает baseline — `deterministic` является дефолтом
   и по построению вне гейта (сама база калибровки), не-базовые
   реализации активируются только явным конфигом. Изменений кода не
   требуется; машинная привязка «конфиг ↔ вердикт калибровки canon» —
   предмет wiring-волны (см. «Ждут владельца/ТЛ»).
4. **§3.7/§4 DP-11 двойной гейт (fix d).** Флаг без ключа больше не
   поднимает исключение: фабрика логирует
   `code=JEV-E-CONFIG class=provider-class` и возвращает
   `DeterministicProvider` — обязательная реакция §4 («конфигурация
   отклонена; активная реализация остаётся deterministic; warn»),
   ноль сети (механический socket-tripwire в тесте). Ключ без флага:
   активация структурно невозможна (ключ читается только на ветке
   `mode=jev`) — тест pin-ует третью комбинацию. Провайдер-уровневый
   `JevConfigError` (пустой ключ при прямом конструировании) сохранён.
5. **§3.8 fail-open для Jev (DP-07).** Добавлена wiring-обёртка
   `JevFailOpenProvider`: отказ транспорта/парсинга на конкретном
   запросе деградирует ЭТОТ вердикт к детерминированному правилу
   (`code=JEV-E-INFER class=verdict-class`); отказ гейта/сканера
   деградирует после единственного `call-class` warn; типизированные
   движковые отказы (`MissingEvidenceError`,
   `UnsupportedPrimitiveError`) проходят насквозь — они неответримы
   для любого провайдера, включая baseline. Калибровочный раннер водит
   RAW-провайдер — честность замера не тронута.
6. **§3.9 телеметрия-атрибуция (DP-09, единственный fail до волны).**
   Новый `log_decision_telemetry`: каждый ответ каждой реализации
   логирует `decision primitive=… provider=… question=… value/probability
   /confidence=…` (key=value дисциплина структурных строк; содержимого
   записей в строке нет). Деградировавший вердикт атрибутируется
   baseline-реализацией — той, что реально ответила (§4 INFER).

## Ждут владельца / ТЛ

1. **Изменение поведения фабрики (решение — рекомендуется принять).**
   `resolve_decision_provider("jev")` при флаге без ключа раньше поднимал
   `JevConfigError`, теперь — warn `code=JEV-E-CONFIG class=provider-class`
   и `DeterministicProvider` (это обязательная реакция §4 контракта).
   Внешних вызывающих в движке нет (ноль call sites), риск — только для
   гипотетических внешних потребителей seam. Рекомендация: принять как
   контрактное поведение; в changelog релиза отметить.
2. **Формат warn-строк (аддитивный).** Строки деградаций получили новое
   поле `class=`; существующие grep-паттерны по `code=CORTEX-E-*` и
   подстрокам продолжают совпадать (проверено тестами). Операторские
   дашборды, парсящие строки строго целиком, не известны — при наличии
   таковых попросить обновить. Рекомендация: принимать как есть.
3. **Секвенция wiring (DP-01).** Точки решений движка ещё не
   маршрутизированы через интерфейс. Решение: какая волна делает wiring
   и заводим ли там же машинную привязку «конфиг ↔ калибровочный вердикт
   canon» (DP-06). Рекомендация: отдельная wiring-волна после этой,
   привязку — туда же.
4. **Ключ без флага — тишина (DP-11).** Диагностический warn при
   «ключ в env есть, но режим не jev» сознательно НЕ добавлен: он срабатывал
   бы у каждого, у кого переменная экспортирована, а работает
   deterministic (шум). Текущая позиция: структурная невозможность
   активации + тест достаточны. Решение нужно только если ТЛ хочет
   видимость «ключа простаивает».
