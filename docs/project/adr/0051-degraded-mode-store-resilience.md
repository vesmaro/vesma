# ADR-0051: Аварийный (degraded) режим записи и resilience-плоскость

- Статус: Ratified (спецификация v2 §7, заочный АрхКом 2026-10-31 — ACCEPT-WITH-CONDITIONS; владелец утвердил план 31.10 «Погнали», включая контрпредложение ТЛ по ВО-3)
- Дата: 2026-11-02
- Спецификация: `handoff/spec-mcp-platform-and-store-resilience-20261031.md` §7 (v2)
- База: 6.9.0 на проде, main da78ce7 (W3), W2 компонент-фронт — носитель спула

## Контекст

В целевой архитектуре (ADR-0050) харнесы пишут через ядро. Недоступность ядра сегодня = громкий отказ соединения у клиентов, у которых нет резерва записи; исторический предшественник — агент-лейн, де-факто «временное хранилище» без signage и схлопывания (инцидент 29.10: неделя записей мимо прода, замечено случайно). Ратифицированное решение: явная машина состояний с спулом, верифицированным реплеем, TTL и многоуровневой сигнализацией.

## Решение

### Машина состояний
```
HEALTHY ──(ядро недоступно: N неудачных проб подряд, дефолт 3)──▶ DEGRADED
DEGRADED ──(проба ОК)──▶ REPLAY ──(100% верифицировано, спул атомарно удалён)──▶ HEALTHY
DEGRADED ──(TTL истёк)──▶ BLOCKED_WRITES ──(ядро восстановлено)──▶ REPLAY
```

- **HEALTHY**: записи в ядро; проба здоровья каждые `poll_interval` (30s, backoff до 10m).
- **DEGRADED**: спул открыт (заголовок: instance, actor, ts первой записи, TTL); ВСЕ записи — в спул; читки — из живых локальных плоскостей с обязательным stale-баннером; signage по матрице ниже. TTL тикает от первой деградированной записи; метка persisted в заголовке спула (переживает рестарты). **Арбитраж источника истины: валидный заголовок спула старше state-файла** — крэш между созданием спула и записью state не теряет degraded-контекст.
- **REPLAY**: спул замораживается; операции проигрываются по порядку через обычный write-API ядра; idempotency — по глобально-уникальному `op_id` + контент-хешу; **re-authz актора на момент реплея** (строка ревокнутого/просроченного токена громко отклоняется со счётчиком, не применяется молча); **правило superseded**: если строка в сторе новее спул-операции (в т.ч. привезённая mesh-федерацией за время деградации) — `superseded`, не перезапись; secret-scan повторяется в момент реплея; после 100% верификации (счётчики planned/replayed/dedup/superseded/rejected) спул переименовывается и атомарно удаляется. Отказ строки — громкий, спул НЕ удаляется.
- **BLOCKED_WRITES** (ВО-3, контрпредложение ТЛ принято в плане): TTL истёк (`max_duration`, **обязательный** конфиг-параметр, дефолт 7d; отсутствие секции = отказ старта клиента, fail-closed) → записи — типизированный отказ `DegradedTTLExceeded` (без раскрытия путей/содержимого спула); **читки сохраняются** (stale, с баннером). Просроченные операции замораживаются в спуле навсегда, никогда не автоудаляются; DR-24 FAIL ведёт на ручной управляемый реплей.

### Спул
- Путь: `<state_home>/vesma/spool/<instance>/<actor>/` — вне всех стор-хоумов (инвариант C6), **0600/0700** (DR-24 проверяет mode/owner, не только возраст).
- Формат: append-only JSONL: `{op_id (глобально уникальный), ts_utc, actor, op, payload, prev_hash}` — per-row hash-chain (детект обрезки/подделки тем же uid); fsync на запись; кейинг per-identity (спулы разных харнесов не смешиваются).
- **Never-weaker**: secret-scan в момент записи в спул (маркировка строки) + повтор на реплее; спул write-only до реплея — содержимое никогда не входит в read-пути.
- Квота: `spool_max_bytes` (дефолт 1 GiB) — исчерпание = BLOCKED_WRITES до разгребания.
- Обрыв хвоста JSONL (потеря питания): реплей толерирует последнюю битую строку (skip-and-report), не абортит весь спул.
- Единый модуль resilience: один resolver состояния (state-файл + flock), общий для фронта, CLI-письмов и hooks; **один reconciler на хост** (сериализация реплея; детерминированный порядок instance-id → op ts); часы — wall-clock с детектором скачка (state хранит last-seen-now; сдвиг > порога → signage + решение по TTL в лог).

### Signage-матрица (Ц5 «не дать забыть»)
| Уровень | Канал | Поведение |
|---|---|---|
| Логи | journald юнита/процесса | WARN при входе в DEGRADED, далее каждые `log_interval` (15m) с возрастом и остатком TTL |
| HTTP | каждый ответ фронта/ядра | `X-Vesma-Degraded: since=…, ttl_left=…`; `/healthz` — поле + счётчики |
| CLI | каждая команда vesma | баннер; `vesma status` — секция |
| Доктор | **DR-24** (зарезервирован, свободен) | спул существует = WARN (возраст, %TTL); >80% TTL или BLOCKED = FAIL; mode/owner спула — проверка; бесхозный спул = WARN-хвост |
| Метрики | metrics-компонент | `degraded_seconds_total`, `spool_bytes`, `spool_ops_pending`; **сбор не требует живого ядра** |
| Агентский | ambient brief / awareness / старт харнеса | строка аварийного режима при каждой сборке контекста |
| Эскалация | 50%/80%/100% TTL | WARN → FAIL |
| **Вне машины** (обязательно) | webhook/notify (`resilience.degraded.notify`) | уведомление при входе в DEGRADED и на 80% TTL |

## Размещение (план волн)
Носитель спула — **компонент-фронт (W2)**: фронт — единственная площадка клиентской записи в целевой архитектуре. Ядро носит только signage-поверхности (заголовок/health — агрегат собственного состояния). W4 реализует: resilience-модуль, спул, машину состояний, реплей, TTL, signage, DR-24, метрики — в ветке `feat/resilience-w4` (ADR в ней и лежит).

## Отклонённые альтернативы
- **Консенсус-репликация (raft-класс)** — отдельный будущий трек: SQLite single-writer закреплён writer-lock (ADR-0049); mesh уже даёт асинхронную мульти-машинную репликацию метаданных; честный multi-writer — переворот движка. Кандидаты HA-перспективы: WAL-shipping (litrestream-класс), горячий резерв ядра на кольце k3s.
- **Кластеризация фронта** — фронту нечего кластеризовать (stateless); точка отказа — хранилище, её закрывает этот ADR + mesh.
- **Полный блок по TTL** (директива-первоначалка) — кирпичит весь флот из-за пропущенной недели; принят контрпредложение «блок записей, читки stale» (решение владельца в утверждении плана).

## Последствия
- Деградация ≠ простой и ≠ тихая расползание: записи продолжаются, схлопывание автоматическое, забвение невозможно по конструкции (вне-машинный канал).
- Латентность деградированной записи = запись в локальный файл (дешевле обычного HTTP-пути) — деградация не замедляет.
- Инварианты платформы не обходятся: реплей идёт через write-API ядра (writer-lock, mint-защита, сканы) — спул никогда не становится «вторым движком».
