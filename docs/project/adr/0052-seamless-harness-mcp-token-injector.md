# ADR-0052: Бесшовный MCP-доступ харнесов — инжектор-прокси токена

- Статус: Accepted (АрхКом 2026-11-06, консенсус 3/3 после фазы критики; Phase 0 host-local деплой 2026-11-06, Phase 1 репо-волна 2026-11-08)
- Дата: 2026-11-08 (протокол и контракт — 2026-11-06)
- Протокол: `~/.gcw/architectural-committee/2026-11-06-mcp-token-seamless-injector.md`; контракт: `~/.gcw/architectural-committee/2026-11-06-mcp-token-seamless-injector-contract.md` (+аддендум — финальная таблица портов)
- База: 6.11.0, main 44147c6

## Контекст

Сессии zcode-харнеса старше суток теряли доступ к памяти (401 на `/mcp`): агент-токен имеет потолок TTL 24ч (ADR-0050 C7), ротация была ежедневной, а клиент харнеса читает конфиг один раз при старте и не перечитывает — TTL = каденсу, окна перекрытия нет. Директива владельца 06.11: митигации («рестартуй сессию», «ротируй чаще») отклонены — требуется бесшовность для сессии любого возраста, критично, реализация немедленно.

Ограничения: ратифицированные инварианты ADR-0050 не подлежат нарушению — потолок TTL 24ч, фронт = носитель идентичности, НЕ авторизатор (C2), fail-closed на `/mcp` без наследования loopback-доверия. Класс угрозы (security): loopback-TCP не имеет uid-границыы — файл 0600 конвертируется в сетевую «никто»; sandboxed-приложения чужих uid получают rw к памяти (stored prompt injection в будущие сессии, CWE-74/LLM01).

## Решение

**Вариант A — локальный инжектор-прокси** между харнесом и ядром (реализовано; канонический артефакт — `src/vesma/mcp_injector.py`, stdlib-only, один модуль, MCP-слепой):

```
zcode-сессии → http://127.0.0.1:8789 (статический Bearer <proxy-secret>)
   → vesma-mcp-injector (systemd --user юнит; на КАЖДЫЙ запрос перечитывает
     токен-файл; зачищает клиентский Authorization; инжектит ровно один
     Bearer <core-token>) → ядро /mcp 127.0.0.1:8787 (fail-closed 401)
```

Ключевые решения внутри A:

1. **Proxy-secret обязателен** (предложение SE, раунд 2): статический секрет листенера (os.urandom 32B, файл 0600) — граница возвращается на файловый уровень (uid); сравнение `hmac.compare_digest`, 403 fail-closed без оракула, порядок «проверил секрет → зачистил Authorization → инжектнул Bearer», секрет никогда не доходит до ядра (T5′).
2. **Ротационный инварант — формула протокола: overlap — инвариант времени, ретрай — инвариант кода; обязательны оба.** Каденс ротации 2×/сутки (04:17+16:17) при TTL 24ч даёт перекрытие ≥12ч (уничтожает окно «истёк-до-mv» в принципе; `issue_agent_token` предыдущие токены не отзывает — проверено кодом agent_tokens.py:613, перекрытие существует by construction); 401-ретрай ровно один ТОЛЬКО при байт-изменении токен-файла закрывает миллисекундную граничную гонку вокруг атомарной подмены. Бесшовность, укладываемая в конфигурацию, не должна опираться на корректность кодовой ветки.
3. **Безопасная поверхность прокси**: бинд строго `127.0.0.1` (IPv4-литерал), peer-check на accept (T6 — defense-in-depth: у loopback-TCP нет uid-границыы), кап тела 2 МиБ (413 + drain), ответ — стриминг без капа, SSE-passthrough чанк-за-чанком с flush (забуферизованный SSE = функциональный дефект: «подвисшие» длинные tool calls), connect-timeout 2с / read-timeout НЕТ (длинные операции не рвать), rate/conn-капы как load-shedding за проверкой секрета (429/503 — не auth-отказ), fail-closed 503 при нечитаемом токен/секрет-файле, старт-рефьюзал без 0600 и владельца-euid, healthz минимальной формы `{ok, token_file_readable, upstream_tcp_ok}` без секретов/путей, структурные логи без тел/заголовков/значений.
4. **Ротация без перезаписи конфига**: config.json харнеса write-once (URL литералом на прокси + секрет); ротационный скрипт минтит токен и атомарно (`mv`) кладёт файл — перезапись конфига скриптом удалена В ОКНЕ флипа (перезапись затёрла бы секрет: поле Authorization вмещает либо ядерный токен, либо секрет, не оба).
5. **Репо-форма (Phase 1, эта волна)**: канонический источник — `src/vesma/mcp_injector.py` (порт живого скрипта 1:1 по поведению); pytest-упаковка слитого смоук-чеклиста (`tests/test_mcp_injector.py`, P0/L/U ноги, T5/T5′/T6/T10, dummy-апстрим на эфемерном порту); doctor-проба **DR-26** (детекция по юниту/процессу; unit inactive → WARN, healthz-down-при-активном-юните → FAIL — класс SPOF доступности; креденшел-файлы не-0600/нечитаемые → FAIL; token-mtime старше 25ч → WARN — ротационная автоматизация остановилась); unitgen-форма `generate_injector_unit()` + `vesma service injector-unit` (юнит из пинов идентичности: порт + токен-файл + секрет-файл = один инжектор на идентичность харнеса). Живой host-local экземпляр продолжает обслуживать прод без изменений — деплой репо-артефакта отложен до следующего обновления хоста.
6. **Инвариант «1 инжектор = 1 идентичность»** закреплён формой: юнит-генератор принимает ровно одну пару креденшел-файлов и один порт; таблица «порт ↔ токен-файл ↔ харнес» живёт в рантбуке (docs).

## Отклонённые альтернативы

- **B (серверный overlap prev+curr)**: не бесшовен по построению — сессия старше 48ч держит токен, который не prev и не curr; конфликтует с ревокационной моделью (отзыв при компрометации обязан рвать всё, prev держит компрометированный токен живым); при клиенте без токена — мёртвая auth-логика с отрицательной ценностью. Security сняла свою исходную рекомендацию B-as-defense-in-depth в раунде 2. Остался опциональным пунктом с узким триггером: эксплуатационные отказы на стыке ротации, не закрытые ретраем, ТОЛЬКО после исключения отката ротационного инварианта как причины.
- **C (долгоживущий креденшел 90д)**: ломает ратифицированный потолок TTL 24ч (ADR-0050 C7); радиус утечки ×90; внеплановая ротация при компрометации воспроизводит исходный дефект в большем масштабе.
- **F (MCP session-id как креденшел)**: идентификаторы сессии не минтятся как секреты, попадают в логи/трассы; обход per-request auth; подрыв W1 (класс CWE-346).
- **A′ (инжект-листенер во фронте)**: фронт становится авторизатором/носителем ядерной идентичности — прямое нарушение C2; один листенер коллапсирует per-harness идентичности W3 — двойное нарушение контрактов ради экономии одного процесса.
- **D (апстрим zcode — credential-refresh при 401/реконнекте)**: истинный терминальный фикс, вне нашего контура; апстрим-карточка = условие списания шима. Sunset-пара: UDS+SO_PEERCRED ИЛИ апстрим D — что первое (при UDS-транспорте харнеса прокси переезжает на сокет с peer-cred, секрет умирает за ненадобностью; вопрос «умеет ли zcode UDS для streamable HTTP» не верифицирован никем).

## Последствия

Положительные:

- Сессия любого возраста переживает любое число ротаций — без правок клиента и без нарушения ни одного ратифицированного инварианта ADR-0050.
- Отказ прокси — громкий и именованный (503 из одного места, journal с peer-строкой на каждый отказ) вместо прежнего молчаливого шторма 401 раз в сутки.
- Деплой нового харнеса = один сгенерированный юнит из пинов (`vesma service injector-unit`), без скриптового зоопарка.

Отрицательные / residual (принятые):

- Статичный proxy-secret — компенсированный residual: компрометация = rw-доступ к памяти до ручной замены (секрет 0600, журнал прокси логирует peer на каждый отказ auth, ручная ротация одной командой).
- Прокси — новая lifecycle-поверхность и SPOF доступности памяти по построению: systemd Restart=always/RestartSec=2, SEC-02-капы (TasksMax/MemoryMax), DR-26 следит; полный отказ = named 503-аутедж для харнесов.
- Миграция = ОДИН разовый рестарт идущих сессий (физический предел однократно-читающего клиента), честно объявлен владельцу; после него возраст сессии значения не имеет.
- Откат ротационного инварианта «период < TTL» на daily молча возвращает суточное окно гонки — инвариант зашит в шапку ротационного скрипта, рантбук и DR-26 (WARN-нога token-mtime).
- GET с телом проксируется без тела (SEC-03, документированное текущее поведение): body-honoring апстрим повиснет и клиент получит 502; MCP streamable HTTP тел с GET не шлёт — дефект недостижим из транспорта.

Операционный контур (Phase 0 → живое): юнит `vesma-mcp-injector.service` (host-local) · секрет `~/.secrets/vesma_proxy_listener_zcode.secret` 0600 · токен `~/.secrets/vesma_zcode_agent_token` 0600 · ротация 2×/сутки таймером (04:17+16:17, Persistent=true) · рантбук флипа/отката — docs (см. «Ссылки»).
